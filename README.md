# Plant disease classification across clean and field images

COMP 664 course project, Topic 2. **Question:** how much does a tomato-leaf classifier trained on clean PlantVillage photographs lose on PlantDoc field images, and does strong crop and color augmentation reduce that loss?

We fine-tune one ImageNet-pretrained MobileNetV3-Small (last block, final convolution and classifier) under two conditions, ordinary vs. strong crop + color augmentation, with three paired seeds (664, 665, 666), eight epochs and new augmented views every epoch. Within a seed both conditions share the initialization and image order. Checkpoints are chosen on PlantVillage validation only and hash-locked before either test set is scored.

| Three-seed mean ± SD (%) | Ordinary | Crop + color |
| --- | ---: | ---: |
| Clean accuracy (PlantVillage, 3,351 images) | 97.26 ± 0.16 | 96.66 ± 0.58 |
| Field accuracy (PlantDoc, 742 images) | 18.78 ± 1.10 | 20.13 ± 0.74 |
| Clean macro-F1 | 96.32 ± 0.18 | 95.71 ± 0.50 |
| Field macro-F1 | 7.76 ± 0.83 | 9.16 ± 0.73 |

Strong augmentation improves field accuracy by +1.35 ± 1.69 pp and macro-F1 by +1.40 ± 1.31 pp on average, but one of the three seeds gets slightly worse. Field accuracy stays far below clean accuracy (a majority-class baseline reaches 10.11%), and most field images are predicted as late blight.

## Run

CPU environment (Python 3.12) for the notebook, demo, analysis and tests:

```bash
cd project
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install --index-url https://download.pytorch.org/whl/cpu torch==2.5.1 torchvision==0.20.1
pip install -r requirements.txt
python analysis.py --results results        # recompute and audit every table from the saved predictions
python -m unittest discover -s tests -v
python demo.py examples/field.jpg
python figures.py                           # regenerate ../report/figures
jupyter notebook ../submission/Tomato_Project.ipynb
```

None of these need the raw images or a GPU. To rebuild everything from raw data (~3.5 GB), use a GPU environment from `requirements-train.txt` (the saved results used PyTorch 2.7.1+cu128 on one RTX 5070 Ti Laptop GPU):

```bash
python data.py --data data                  # download pinned snapshots, rebuild the manifest in reconstructed/
python train.py --data data --out rerun --device cuda
python analysis.py --results rerun
python replay.py --data data --seed-dir results/seed_664
```

`train_longleaf.sbatch` runs the same training as a one-GPU Longleaf job. Rebuilt manifests were byte-identical to `results/manifest.csv`. Replaying all six saved checkpoints on the raw test images reproduced all 24,558 predicted labels (maximum probability difference 0.0003; `results/replay_verification.json`). Replay must use the deterministic settings in `train.deterministic()`; without them 4 near-boundary predictions of seed 664 changed (`results/replay_precision_diagnostic.json`).

## Provenance

The six models were trained by `experiment_fresh.py` (its SHA-256 is recorded in `results/protocol.json`); that script, an earlier single-seed pilot experiment and the original evidence files are in commit `adb96c0`. The code was later consolidated into the files above. On a synthetic dataset covering duplicates, label conflicts, Windows-invalid names and EXIF rotation, the old and new code produced identical downloads and manifests, bit-identical checkpoints, identical histories, byte-identical predictions and metric tables, and identical replay results. On the saved results, `analysis.py` and `figures.py` reproduce every saved table, report macro and figure exactly.

## Limitations

Validation has no mosaic-virus examples. 4,280 training and 1,060 clean-test images lack leaf IDs, and exact-byte checks cannot rule out near-duplicates. Only two spider-mite field images exist. Three seeds describe optimization variability, not variation across farms or datasets. The three-seed study was designed after inspecting the pilot's field results, so it is exploratory evidence on an already examined benchmark.
